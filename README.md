# Playerok Garant

Telegram-бот и Telegram Mini App для организации сделок между покупателем и продавцом. Проект включает Express API, Telegraf, SQLite, пользовательский интерфейс и отдельную серверно-защищённую админ-панель.

> **Важно о деньгах.** Балансы в текущей версии — только внутренний учёт. Они не являются банковскими/электронными деньгами и не подтверждают получение средств. В проекте намеренно нет фиктивной оплаты. Перед реальным запуском нужно заключить договор с законным платёжным провайдером, реализовать проверку подписанных вебхуков, возвраты и выплаты по документации провайдера и требованиям вашей юрисдикции. Ручное изменение статуса оплаты заблокировано.

## Стек
- Node.js 20+

- SQLite через better-sqlite3

## Локальный запуск

1. Установите Node.js 20 или новее.
2. Скопируйте `.env.example` в `.env`.
3. Создайте бота через [@BotFather](https://t.me/BotFather), скопируйте токен в `BOT_TOKEN`.
4. Укажите публичный HTTPS адрес приложения в `APP_URL`. Для локального тестирования используйте HTTPS-туннель.
5. В `ADMIN_IDS` укажите числовые Telegram ID администраторов через запятую.
6. Выполните:

```bash
npm install
npm run check
npm start
```

Сервер отвечает на `/health`. Откройте `APP_URL` только через кнопку Mini App в Telegram, иначе сервер не получит подписанные `initData`.

## Настройка BotFather

1. Откройте @BotFather → `/newbot`, задайте имя и username.
2. Сохраните выданный токен в переменную `BOT_TOKEN` на сервере. Не вставляйте его в HTML, JavaScript, GitHub или сообщения.
3. Используйте `/setmenubutton` или настройки бота → **Configure Mini App / Menu Button**, укажите HTTPS `APP_URL` и название `Playerok Garant`.
4. Установите описание и аватар бота по желанию.
5. В Mini App должна быть доступна та же HTTPS-ссылка, что указана в `APP_URL`.

Бот также отправляет кнопку Web App при `/start`. Если задан `WELCOME_PHOTO_URL`, бот отправит баннер с приветствием.

## Railway

1. Создайте GitHub-репозиторий и загрузите в него все файлы проекта, включая папку `public`.
2. В Railway выберите **New Project → Deploy from GitHub Repo** и подключите репозиторий.
3. Railway определит Node.js и выполнит `npm install`; команда запуска: `npm start`.
4. В Variables добавьте `BOT_TOKEN`, `APP_URL`, `ADMIN_IDS`. Не загружайте `.env` в GitHub.
5. Сгенерируйте домен Railway, затем установите этот HTTPS адрес в `APP_URL` и в BotFather.
6. Для постоянного хранения SQLite добавьте Railway Volume и установите `DATABASE_PATH` в путь внутри примонтированного volume, например `/data/playerok-garant.sqlite`.
7. После деплоя проверьте `https://ваш-домен/health` — ожидается `{"service":"Playerok Garant","status":"running"}`.

## Что реализовано

- `/start`, приветствие и кнопка открытия Mini App.
- Проверка Telegram WebApp `initData` на сервере (HMAC-SHA256, срок действия 24 часа); Telegram ID берётся только из подписанных данных.
- Профиль пользователя и нулевые учётные балансы RUB, UAH, BYN, TON, XTR.
- Создание сделки, приглашение по уникальной ссылке, выбор роли вторым участником.
- Роли покупателя/продавца; подтверждение получения доступно только покупателю и только на разрешённых этапах.
- Открытие спора участником сделки.
- Админ-панель: список пользователей, сделок, финансовых записей, аудит; смена статуса; обработка спора; внутренняя учётная корректировка с аудитом.
- Валидация входных данных, ограничение размера JSON, rate limit API, Helmet, параметризованные SQL-запросы, экранирование пользовательских данных на клиенте.

## Ограничения и следующие интеграции перед реальным использованием

- Пополнение, списание и выплаты реальными средствами не подключены. Нужны провайдер и серверная проверка подписи каждого webhook; никогда не доверяйте статусу из браузера.
- XTR/Telegram Stars требуют отдельной реализации invoice, `pre_checkout_query` и проверки `successful_payment` на стороне бота.
- TON требует интеграции с проверяемым индексатором/провайдером и подтверждения on-chain транзакции.
- Отмена и возврат денег не исполняют платежи: возвраты должны проходить через исходного провайдера и его API.
- Для промышленной эксплуатации добавьте резервное копирование SQLite, мониторинг, политику хранения персональных данных, юридические документы и процедуру поддержки/арбитража.
- SQLite подходит для небольшого запуска. При высокой нагрузке лучше PostgreSQL и миграции схемы.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота |
| `APP_URL` | Публичный HTTPS URL Mini App |
| `ADMIN_IDS` | Разрешённые Telegram ID администраторов через запятую |
| `DATABASE_PATH` | Путь к SQLite |
| `PORT` | Порт HTTP сервера |
| `WELCOME_PHOTO_URL` | Необязательный HTTPS баннер для `/start` |
| `DEV_AUTH_BYPASS` | Только локальная разработка; в production должно быть `false` |
